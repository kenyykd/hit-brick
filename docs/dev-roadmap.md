## 如何使用這份文件

- 階段依**實際動手順序**排列，不是依討論編號。
- 每個階段做完、通過「驗收標準」，才進下一階段。
- 標示 **[首發]** 的階段都完成後才發布第一版；**[首發後]** 是之後的更新。
- 相對工作量只是粗估：小 / 中 / 大。

## 一、已定案決定總表

### 技術路線
| 項目 | 決定 |
|---|---|
| 技術 | 維持純 JS + CSS + Canvas，不換遊戲引擎 |
| 工具 | 加入 Vite，程式拆成 ES Modules，與第 1 階段重寫一起做 |
| Canvas / DOM 分工 | 遊戲畫面（球、磚、板、粒子）用 Canvas；選單、分數、暫停、結算、按鈕用 HTML + CSS 疊在上面 |
| 框架 | 不用 React / Vue 寫遊戲主體 |
| Matter.js | 從核心移除，球與球拍、磚塊全用自己寫的碰撞；日後如做磚塊碎片掉落，再當純視覺特效請回來 |
| 時間步長 | 固定 120Hz 邏輯更新，畫面繪製跟著螢幕更新率 |
| 測試 | Vitest；碰撞、反彈、迴圈等純函式寫單元測試，另有 10 分鐘最高球速的無畫面模擬 |

### 場地與操作（手機優先）
| 項目 | 決定 |
|---|---|
| 場地比例 | 直式；邏輯寬度固定 540，高度依螢幕比例在 960（9:16）～1200（9:20）之間伸縮，手機填滿，電腦用 9:16 置中；橫放時提示轉回直式，不做橫向版面 |
| 板子操作（手機） | 發射後相對拖曳，手指不用壓在板子上；板子離底部留距離避開系統手勢區 |
| 發射（手機） | 彈弓式：發射前板子不動，手指在任意處按住往後拉，拉的反方向就是發射方向，放開發射；沒拉就放開（單點）用預設角度；往上拉放開 = 取消；磁鐵重新瞄準用同一套 |
| 統一輸入 | 電腦與手機都轉成三種事件：板子目標位置、瞄準方向、發射；遊戲邏輯不分裝置 |
| 按鈕位置 | 技能鈕在底部角落（至少約 48px）、暫停鈕在上方角落；避開安全區域 |
| 電腦按鍵 | 預設：滑鼠移動或 ← → / A D 移板子；發射前 ↑ ↓ / W S 調瞄準角度；滑鼠按住拖曳 = 彈弓瞄準、點擊發射；空白鍵持球時發射、沒持球時施放技能；右鍵施放技能；Esc 或 P 暫停。**按鍵可自訂**（鍵位是資料，改鍵介面在設定頁） |

### 核心玩法
| 項目 | 決定 |
|---|---|
| 球拍反彈 | 由擊中位置決定角度，最大約 ±55 度，用公式不用物理 |
| 速度 | 每次碰撞後正規化回目標速度；限制最小垂直角度（約 15 度） |
| 防穿透 | 子步驟法：每次移動不超過約半個球半徑 |
| 同時碰多磚 | 一個子步驟只處理最近的一塊 |
| 發射 | 限制向上的角度範圍，球一定往上發射 |

### 關卡
| 項目 | 決定 |
|---|---|
| 數量 | 首發 20 關，手工設計 |
| 解鎖 | 線性解鎖（過一關才開下一關） |
| 磚塊（第一批） | 普通、多次擊破（2～3 下）、不可破壞、爆炸（炸十字 4 格，可連鎖，連鎖每深一層多 5 分）；每種磚除了顏色還有形狀記號，色盲可分辨 |
| 磚塊（第二批，首發後） | 移動磚、隱藏獎勵磚、再生磚、傳送磚 |
| 過關條件 | 打掉所有「可破壞」的磚 |
| 資料 | 關卡是獨立資料，用文字方塊排列設計；包含編號、目標分數、主題、球速；欄數 9～10 欄，磚塊大小依畫布寬度自動計算。字元：`.` 空格、`N` 普通、`2` / `3` 多次擊破、`#` 不可破壞、`*` 爆炸 |
| 關卡驗證 | 載入時檢查格式（欄數、每列長度、字元、球速、主題）；測試另外檢查「不可破壞磚不會封死可破壞磚」 |

### 道具
| 項目 | 決定 |
|---|---|
| 第一批六個 | 多球、加長球拍、減速球、火球、磁鐵（停在板子上重新瞄準，已合併原「黏球拍」）、加一命 |
| 負面道具 | 首發不做 |
| 掉落 | 約 12% 加保底機制，各道具有不同權重 |
| 疊加 | 同種道具刷新時間；效果對場上所有球生效 |
| 火球 | 遇不可破壞磚仍反彈；爆炸磚照常爆炸；持續時間設最短 |
| 多球 | 場上所有球都掉落才扣命；球數上限 8 顆 |
| 清除 | 失去生命或過關時，清除所有道具效果與掉落中的膠囊 |
| 計時 | 用遊戲時間，不用真實時間（暫停時一起暫停） |
| 辨識 | 膠囊用顏色加圖示，色盲也能分辨 |
| 第二批（首發後） | 吸引膠囊、球變大等；雷射與安全網已改為板子技能，不放進道具 |

### 板子與技能
| 項目 | 決定 |
|---|---|
| 結構 | 板子是資料（外觀、寬度、手感、反彈角度範圍、專屬技能），第 1 階段就預留資料驅動 |
| 首發 | 標準板（無技能）、雷射板（寬 88，比標準板窄）、護盾板 |
| 技能能量 | 以打磚塊為主（每塊 +1/15，約 15 塊集滿）、時間為輔且有上限（只在球飛行時，最多充到 30%）；雷射打掉的磚不給能量；失去生命保留能量；過關重置 |
| 護盾 | 底部出現一道護盾，接住第一顆從上方掉下來的球就消失，沒有時限；失去生命或過關時清除 |
| 雷射 | 施放後 4 秒內每 0.25 秒從板子兩端各射一發，打到第一塊磚就消失；不可破壞磚擋住；多次擊破磚每發扣 1 下 |
| 施放 | 玩家手動；電腦空白鍵（沒持球時）或右鍵，手機用右下角按鈕；上一次的技能還在時不能再放 |
| 平衡基準 | 關卡以標準板為基準設計，其他板子再微調 |
| 解鎖 | 累積星星：護盾板約 10 顆、雷射板約 25 顆 |

### 遊戲流程
| 項目 | 決定 |
|---|---|
| 畫面 | 主選單、選關、選板子、遊戲中、暫停、過關、失敗、通關；全用 HTML + CSS |
| 生命 | 每關從 3 條開始（不帶到下一關），上限 5 條；歸零只重玩該關 |
| 暫停 | 所有東西一起停；切分頁、鎖屏、來電、Android 返回鍵自動暫停；恢復倒數 3 秒 |
| 連擊 | 球連續打破磚（含爆炸連鎖）、中間沒碰到板子就累加；碰到板子或失去生命歸零；每 5 連擊 +1 倍（1～4 連擊 1 倍、5～9 連擊 2 倍……），上限 4 倍 |
| 計分 | 每關各自計分（從 0 開始，不跨關累積）；不同磚塊給不同分數，爆炸連鎖遞增；過關時才記錄該關最高分 |
| 存檔 | localStorage 加版本號；讀不到時仍可遊玩（只是不保存）；讀取失敗用預設值，不白屏；毀損的原始內容另存一份備份 |
| 新手引導 | 情境式提示（新元素首次出現時說明一次），不另做教學關；提示文字依裝置切換 |
| 移除 | 所有 alert 與 reload，遊戲內文字改 HTML 顯示 |

### 打擊感與音效
| 項目 | 決定 |
|---|---|
| 架構 | 事件驅動：遊戲邏輯只發事件，音效與特效各自訂閱；純表現、不影響判定、可整層關掉 |
| 音效 | 首發以程式合成（8-bit 風格）為主；破磚音效連擊升調；同時發聲數量與同種音效頻率有上限 |
| 音樂 | 首發 1～2 首循環，壓縮；不等音樂載完才能開始遊戲 |
| 特效品質 | 高 / 中 / 低三檔加自動降級；尊重系統「減少動態效果」 |
| 畫面震動 | 預設只在爆炸與失去生命時觸發，可關閉 |
| 設定項目 | 音效、音樂、特效品質、畫面震動、手機震動，各自獨立開關 |
| 音效啟動 | 主選單「開始」按鈕兼任解鎖音效（手機瀏覽器限制） |

### 長期留存
| 項目 | 決定 |
|---|---|
| 星星 | 每關最多 3 顆：過關、達到目標分數、未失去生命；只增不減，取歷史最佳 |
| 目標分數 | 自動計算：可破壞磚的基礎總分 × 1.6（要靠連擊才拿得到），取到十位；第 1 關用 1.2 倍讓三星容易；關卡可用 `targetMultiplier` 或 `targetScore` 個別覆寫 |
| 板子與皮膚 | 分開；皮膚純外觀，不改判定與速度；首發球 4 款（經典白、黃金、霓虹、像素）、板子外觀 4 款（純色、條紋、漸層、發光），全部用 Canvas 程式畫；火球生效時球一律畫成橘色（遊戲資訊不被皮膚蓋掉） |

| 成就 | 首發 15 個，事件驅動；分進度、技巧、探索三類；達成時上方提示框，不打斷遊戲（清單見下方，歡迎增刪） |

### 後端與商業化
| 項目 | 決定 |
|---|---|
| 首發 | 不做後端；之後可能加入。後端永遠只是可選加值層，遊戲永遠能離線完整遊玩 |
| 架設方式 | 沒有本地 NAS 可用，所以一律用現成的雲端後端服務，不自架伺服器 |
| 順序 | 雲端存檔 → 排行榜 → 商業化 |
| 排行榜 | 輕量檢查加分榜，不做完整重播驗證；每關、每日挑戰、無盡各一榜；標準板為主榜或各板子各自一榜；自製關卡成績不上榜 |
| 暱稱 | 開放自由輸入，但要擋會被當成腳本執行的字串（見第四節「暱稱安全」） |
| 商業化原則 | 板子只能靠星星解鎖；付費只限外觀；廣告若有，只在結算畫面且自願觀看；不做付費牆、不為促進付費刻意調難 |
| 預留 | 現在只預留統一的「同步存檔 / 提交成績」介面，預設什麼都不做；存檔先預留匿名玩家編號欄位 |

## 二、貫穿所有階段的架構原則

1. **球是陣列。** 從第一天起所有碰撞都能處理多顆球。
2. **事件系統。** 遊戲邏輯發事件（磚塊被打破、球碰板、接到道具、連擊增加、技能施放），音效、特效、成就都只訂閱事件。事件要帶足夠資訊（磚塊類型、連擊數、是否爆炸連鎖）。
3. **資料驅動。** 關卡、磚塊、道具、板子、皮膚、成就、解鎖條件都是資料，新增內容不動核心。
4. **遊戲時間。** 所有倒數與能量都用遊戲時間，暫停與切分頁時不前進。
5. **表現層可關閉。** 特效、音效、震動出問題時，整層關掉遊戲仍正常。
6. **不可信資料一律驗證。** 匯入的存檔、關卡、暱稱都要檢查格式、大小、數值範圍。
7. **碰撞邏輯寫成獨立的純函式。** 方便單獨測試，不依賴畫面。

### 階段 1：核心重寫 [首發]（工作量：大）

這是整個專案的地基，後面所有項目都建立在它上面。

**要一起解決的現有問題**
1. 球有兩套座標（目標位置加平滑）→ 改成單一座標。
2. 球速綁在畫面更新次數 → 改固定時間步長。
3. 同一幀碰多磚全部處理 → 只處理最近一塊。
4. 球拍最大角度實際只有約 ±30 度 → 改為約 ±55 度。
5. 球拍可被拉出畫面 → 限制在畫面內。
6. 發射方向無限制，點到球正上方會算出無效數值 → 限制向上的角度範圍，並處理距離為 0。
7. 球拍快速移動可能穿過球 → 碰撞判定要考慮球拍這一幀的移動。
8. 移除 Matter.js 及它獨立的更新迴圈。

**工作項目**
- [x] 固定 120Hz 邏輯步長；累積時間；限制單幀最多補幾步（避免卡頓後一次補太多）。
- [x] 子步驟防穿透。
- [x] 圓形對矩形碰撞，穿透後把球推出磚外。
- [x] 球拍反彈用公式；速度正規化；最小垂直角度。
- [x] 球改陣列；球拍改資料驅動（寬度、反彈角度、手感由設定檔讀取，目前只放標準板）。
- [x] 事件系統骨架。
- [x] 統一輸入層：板子目標位置、瞄準方向、發射；手機相對拖曳；拖曳與點擊用移動門檻區分。
- [x] 直式場地、高解析螢幕處理（倍率有上限）、避免瀏覽器預設行為（下拉重整、雙擊縮放、長按選取、捲動）。
- [x] 使用動態視窗高度，不用固定視窗高度（手機網址列會伸縮）。

**驗收標準**
- 60Hz 與 144Hz 螢幕上，球速（每秒移動距離）一致。
- 以最高球速連續玩 10 分鐘，球不穿磚、不卡磚。
- 同時碰到兩塊磚只處理最近的一塊。
- 打板子邊緣角度明顯偏斜，打中間偏直。
- 球不會水平來回無限彈跳。
- 點球下方或球正上方，球都往上發射。
- 板子不會出界。
- 手機直式填滿、畫面不模糊。
- 切分頁再回來，球不會暴衝。
- 專案中已沒有 Matter.js 的核心依賴。

**依賴**：階段 0。

### 後端（階段 D 的內容）

**原則**
- 遊戲本體永遠不依賴後端；後端壞了遊戲照常能玩。
- 沒有本地 NAS，用現成雲端後端服務；選哪一個，到要做的時候再比較當時的費用與限制。
- 設定費用上限、用量警示與請求頻率限制，避免被刷或突然爆紅時帳單失控。
- 備份與還原流程要實際演練過一次。

**順序**
1. **雲端存檔**：匿名帳號加恢復碼；合併規則為「絕不讓玩家進度變少」——星星取最大值、解鎖取聯集、各關最高分取最大值、成就取聯集、設定以最近修改為準；過關或解鎖時在背景同步，失敗時靜默重試；要有隱私權政策與「刪除我的資料」。
2. **排行榜**：輕量檢查（成績合理範圍、提交頻率限制、異常值拒絕）加檢舉與手動移除；每關、每日挑戰（統一用世界標準時間）、無盡模式各一榜；板子分開計算；排行榜讀不到時顯示「目前無法連線」，不影響其他功能。
3. **商業化**（越後面越謹慎）：自願支持連結 → 外觀付費 → 廣告（可以不做）。開始收費前，先確認金流、稅務與登記需求並諮詢專業人士。

### 視覺加強想法（最後再做）

階段 4 實機測試後提出，放到最後開發；做的時候沿用階段 5 的事件驅動特效層（純表現、可整層關掉、尊重特效品質與「減少動態效果」）。

- [ ] **火球像真的火**：火球道具期間，球改成火焰外觀（火焰粒子、閃爍光暈、往後飄的火舌），取代目前單純變橘色。粒子用物件池，低檔特效時退回簡化版。
- [ ] **火球撞擊震動**：火球撞到磚塊或牆時畫面震動。注意：已定案「畫面震動預設只在爆炸與失去生命時觸發」，這項要做成小幅度、有冷卻時間，並受設定頁「畫面震動」開關控制。
- [ ] **球加速殘影**：球速越快殘影越明顯（依目前速度調整殘影長度與透明度）；可與階段 5 的「球拖尾」共用同一套實作。

### 暱稱安全（已定案：自由輸入）

自由輸入的暱稱要同時做到：
- **顯示時一律當純文字**（用 `textContent`，絕不用 `innerHTML` 拼接）。這是真正防止腳本被執行的關鍵，不能只靠字串過濾。
- 前端與後端**都要驗證**（後端才是最後一道，前端驗證可以被繞過）：長度上限（例如 2～12 字）、只允許文字、數字與少量符號、去掉控制字元與 `<`、`>`、引號等特殊符號。
- 擋掉會被當成腳本或網址的字眼（例如 `script`、`javascript:`、`on…=`、`http` 等），這是額外的一層，不是主要防線。
- 另外要有不雅字眼過濾，並提供檢舉與手動移除。
- 暱稱不要放進網址參數或未經跳脫的地方。

- 板子不是資料 → 加板子要重改核心。
- 時間沒有區分遊戲時間與真實時間 → 暫停會出各種問題。
